# 把 GO 账户系统真正启用

代码已支持邮箱／手机号加密码登录、邮箱／短信验证、独立云端资料和只读管理员后台。**仅上传网站代码不会自动创建数据库、发送验证码或授予管理员权限。** 未配置服务时，网站明确显示浏览器本地预览模式，不会假装已开通注册。

## 你需要准备什么

- 一个你自己的邮箱，用来注册 GO，并成为后台管理员。不需要把邮箱密码发给开发者。
- 一个你拥有的 [Supabase](https://supabase.com/dashboard) 项目。
- 网站现有的 Vercel 项目权限。
- 面向所有人的邮箱验证码需要配置邮件发送服务；手机号验证码需要短信服务。它们可能有发送额度或费用，应先在服务商控制台确认。

## 1. 创建保存账户的服务

1. 打开 Supabase，登录后选择 New project。
2. 项目名称填 `GO`，选择适合的区域。数据库密码自己保存，**不要发在聊天里**。
3. 等待项目创建完成。
4. 可以打开网站的 `/setup.html`，点击“复制全部 SQL 代码”，再打开其中的 SQL Editor 链接、粘贴并点击 Run。也可以直接打开 SQL Editor，创建一个查询，粘贴仓库的 `supabase/migrations/202611040001_go_accounts.sql`，点击 Run。

这份 SQL 创建独立资料表、数据库级权限、带版本检查的保存接口和管理员读取接口。项目建议专用于 GO。后台会列出该项目的注册账户，不能把不相关产品的用户混在同一个项目中。

## 2. 连接网站

在 Project Settings → Data API / API Keys 中找到：

- 项目 URL，类似 `https://xxxx.supabase.co`。
- Publishable key（公开密钥，通常以 `sb_publishable_` 开头）。旧项目可使用 anon key。

打开 Vercel → GO 项目 → Settings → Environment Variables，添加：

```
VITE_SUPABASE_URL=你的项目URL
VITE_SUPABASE_PUBLISHABLE_KEY=你的公开publishable key
```

**不要使用 service_role key、`sb_secret_` key、数据库密码或项目管理令牌。** `VITE_` 配置会进入浏览器，只有公开 URL 和公开 key 可以放进去。

如果由开发者协助连接，也可以把这两个**公开配置**写入 `src/accounts/project.public.json` 的 `url` 和 `publishableKey`，再正常推送部署。该文件会进入浏览器，不允许写入任何私钥、数据库密码或管理员邮箱。完整的 Vercel 环境变量会优先于这个文件；不完整的变量会报错，不会混用两个项目的 URL / key。构建会拒绝任何来源的 service_role 或 sb_secret_ key。

为 Production 环境保存变量后，重新部署网站；仅设置变量不会改变已经构建好的版本。本地开发可以复制 `.env.example` 为 `.env.local`，填写上述公开配置后重新启动 Vite。

## 3. 打开邮箱验证

在 Supabase → Authentication：

1. 启用 Email provider。保持邮箱验证开启。
2. URL Configuration → Site URL 填 `https://1-xi-five-69.vercel.app`，允许该站点的 `/`、`/auth/callback` 和 `/auth/reset-password` 返回地址。开发时按需加入明确的 localhost 地址，不要对生产地址使用任意域名通配符。
3. 注册使用邮箱和密码，并通过确认邮件验证邮箱；之后默认用密码登录。保留默认确认链接邮件模板即可。登录页也支持验证码／邮件链接作为替代方式；如果要显示数字验证码，可在 Magic Link 邮件模板中加入 `{{ .Token }}`。Reset Password 模板应保留 `{{ .ConfirmationURL }}`，供用户打开设置新密码的页面。
4. 面向真实用户时，在 Authentication 的 SMTP 设置接入你自己的邮件服务，并完成该服务要求的发信域名验证。Supabase 内置测试发信服务有严格限制，可能只允许团队邮箱，不能当作无限量公众邮件服务。
5. 保持 Supabase 自带的验证码有效期、发送频率和防滥用限制。公开发布前根据项目规模配置适当的防滥用措施。

注册需要姓名、联系邮箱／手机号、至少 8 位密码、重复确认密码和资料告知确认。保持邮箱和手机号验证开启，通过验证后才允许登录。已有邮件链接账户不用重新注册：登录后打开 **Account → Set or change password** 设置密码。邮箱用户可用 **Forgot password?** 获取重置链接；手机用户可通过短信验证码登录后设置密码。密码由 Supabase Auth 处理，不写入个人健身资料或管理员目录。数据库不把用户自己填写的 `admin` 或 `role` 字段当成管理员身份。

## 4. 手机验证码

在 Authentication → Phone provider 中启用手机登录，接入 Supabase 支持的短信服务商，例如 Twilio，并在服务商处配置所需发送号码/发送身份和发送地区。

手机号采用带国家码的格式，例如 `+14155552671`。没有短信服务商配置时，手机验证码不能送达，网站会显示失败或暂不可用，不会提供虚假验证。可以先把邮箱账户启用，稍后配置短信。验证码与密码不会显示在管理员后台。

已有账户的用户应在 **Account** 页面验证并绑定另一种联系方式，不要另外注册一个新账户；否则可能创建另一份独立资料。邮箱变更使用邮件确认链接；启用安全邮箱变更时可能需要确认新旧两个邮箱。手机号变更使用短信验证码。

## 5. 让你成为管理员

1. 用你自己的邮箱在 GO 创建账户并完成验证。
2. 在 SQL Editor 中打开 `supabase/assign-admin.sql` 的内容，把示例邮箱替换成你刚验证的邮箱，运行。
3. 重新登录／刷新 GO，打开 `https://1-xi-five-69.vercel.app/admin`，或者点击账户登录后出现的 Admin。

管理员资格保存在不可由普通用户写入的 `go_private.admin_users` 表。不能只改网页变量、用户资料或浏览器 localStorage 来成为管理员。普通用户直接访问 `/admin` 会被拒绝；后台接口也会再次检查数据库权限。

需要取消管理员时，由项目所有者在 SQL Editor 删除对应的 `go_private.admin_users` 行；权限检查立即影响后续后台请求。不要把数据库管理权限交给一般用户。

## 后台能看到什么

- 注册用户的姓名、邮箱、手机号及各自的验证状态。
- 注册时间、最近登录时间、目标，以及用户已经保存的身体信息、训练偏好和活动记录。
- 搜索与分页、用户详情、注册/验证/近七天登录人数。
- 管理员查看目录和详情会写入独立访问日志。

后台是只读的，不提供修改他人训练或随意授予管理员的按钮。它不能识别尚未注册的匿名访客，也不包含验证码、登录令牌或密码。

## 旧资料与跨设备保存

- 未连接服务时，旧版资料只在浏览器 `forma-v2` 中。
- 登录后的资料按 Supabase user ID 隔离，使用服务器云端副本，不自动读取其他账户或未登录本地资料。
- 有旧资料且新账户没有进度时，用户可以明确选择导入自己的本地记录，或者从空白账户开始。
- 同一账户多台设备同时修改会出现版本冲突提示，不会静默覆盖新资料。用户可先下载当前资料，再加载服务器版本。
- 网络错误会保留当前页面未同步的修改并提供重试；页面关闭提醒不能代替备份。不承诺离线关闭页面后恢复尚未上传的数据。

## 上线前验证与限制

已提供 PostgreSQL/PGlite 权限测试及可控 API 传输下的浏览器流程测试。这些证明代码行为，但**不能代替你自己项目上的真实邮件和短信送达验证**。

用两个实际邮箱、两台设备依次完成注册、退出、换账号、保存/刷新、管理员查看及普通用户拒绝访问；手机号还需用真实号码测试收到验证码。不要使用测试验证码作为线上通行码。

`public/privacy.html` 说明了收集和管理员可见范围。正式邀请公众注册前，站点所有者应补上直接的支持/删除请求联系方式，核对服务商、留存与运营要求。当前没有自动删除账户或承诺自动过期删除的功能。
